# HamHeatmap Phase 0 验证报告

- 日期：2026-07-16
- 状态：首轮核心验证通过；尚非桌面 MVP
- 主机：Ubuntu 22.04.3 LTS，x86_64，16 逻辑 CPU，57 GiB RAM

## 1. 固定版本

- Rust `1.97.0`，Cargo `1.97.0`，项目内工具链。
- GCC/G++ `11.4.0`。
- NTIA ITM `v1.4`，提交 `668e4ab0b31a7ea1e949e4824272955d63e7c731`。
- `tiff 0.11.3`，只启用 Deflate；精确传递依赖由 `Cargo.lock` 固定。
- 模型默认值版本 `phase0-v1`，见 ADR-0001。

上游 ITM 源码保持原样。因 v1.4 的 `.cpp` 使用 Windows 反斜杠 include，`build.rs` 只在 Cargo 输出目录生成路径可移植的临时编译副本。

## 2. 自动验证

- `cargo test --workspace --all-targets --locked`：通过。
- Rust 单元测试：7 个通过。
- NTIA `p2p.csv`/`pfls.csv`：5 组官方 point-to-point 参考案例全部在 0.011 dB 容差内通过。
- `cargo clippy --workspace --all-targets --locked -- -D warnings`：通过，零 warning。
- 功率、增益、自由空间诊断、PFL 结构、1 km 最近网格点和 GeoTIFF tiepoint 均有测试。

NTIA 返回码 `1` 是“成功且有 warning”，不是模型错误。包装层保留 warning 位；负数包装错误和 1000 以上 ITM 错误才阻断结果。

## 3. 合成地形验证

参数为垂直极化、100 km、发射高度 20 m、接收高度 1.5 m、`phase0-v1` 地表参数。

| 地形 | 频率 | ITM 模式 | 基本传输损耗 | 接收功率（25 W、6/-3 dBi） | warning |
|---|---:|---|---:|---:|---:|
| 平地 | 145 MHz | Troposcatter | 180.780 dB | -133.801 dBm | `0x0` |
| 800 m 中央山脊 | 145 MHz | Diffraction | 216.574 dB | -169.594 dBm | `0x1000` |
| 800 m 中央山脊 | 435 MHz | Diffraction | 230.574 dB | -183.595 dBm | `0x1000` |

同频率山脊增加约 35.79 dB 损耗；同一山脊下 435 MHz 比 145 MHz 增加约 14.00 dB。地形和频率均确实进入模型。

## 4. 1 km 网格边界

原方案在 1 km 使用自由空间、1.001 km 使用 ITM，会从约 75.68 dB 跳至 89.22 dB，产生约 13.5 dB 人工不连续。产品固定 1 km 网格中，中心像素是发射点且无接收结果，最近的四个有效像素恰好为 1.0 km。ITM v1.4 在 1.0 km 返回成功、无 warning，因此所有 125,628 个非中心圆内像素统一使用 ITM。详见 ADR-0002。

## 5. GLO-90 真实数据

- 区域：N30/E103（四川盆地西缘附近）。
- AWS 对象：`Copernicus_DSM_COG_30_N30_00_E103_00_DEM.tif`。
- 大小：5,169,591 bytes。
- SHA-256：`2009766e446d6a33537e013dc0fa1944ce51857b0574182583e2d35eca2a8ab8`。
- 栅格：1200×1200，32-bit float，Deflate，3 arc-second（0.000833333333°）。
- 有效样本：1,440,000；NoData：0。
- 高程：397.5–5181.798 m，均值 960.668 m。
- 纯 Rust 完整解码：约 0.0886 秒。

固定路径从 `(103.05, 30.50)` 到 `(103.95, 30.50)`，距离 86.228 km，以约 90 m 间距取得 960 个真实高程样本，范围 467.0–2030.6 m：

| 频率 | ITM 模式 | 基本传输损耗 | warning |
|---:|---|---:|---:|
| 145 MHz | LineOfSight | 159.953 dB | `0x200` |
| 435 MHz | LineOfSight | 179.272 dB | `0x200` |

`0x200` 表示发射端地平线距离小于平滑地球地平线距离的 1/10，作为诊断保留，不当作错误吞掉。

## 6. 401×401 全圆核心基准

圆半径固定 200 km、1 km 间距、中心无结果，共 125,628 个 ITM 接收点。每条合成剖面目标采样间距 90 m。下表为 145 MHz 平地 release 构建；不同线程的损耗与模式统计完全一致，错误均为 0。

| 线程 | 耗时 | 点/秒 | 峰值 RSS |
|---:|---:|---:|---:|
| 1 | 2.522 s | 49,821 | 4,972 KiB |
| 2 | 1.520 s | 82,648 | 5,004 KiB |
| 4 | 0.861 s | 145,915 | 5,136 KiB |
| 8 | 0.499 s | 251,731 | 5,396 KiB |
| 16 | 0.282 s | 445,220 | 5,684 KiB |

16 线程、435 MHz 山脊场景为 0.364 秒、344,942 点/秒、5,692 KiB RSS、0 error。山脊合成几何触发大量合法 warning，后续必须按位汇总而不是隐藏。

结论：ITM 调用和合成剖面构建不是 60 秒目标的主要风险，四线程核心有充足余量。但该数字不包含真实 200 km 多瓦片定位/解码、剖面射线采样、SQLite、UI 渐进渲染、Windows 调度和导出，不能宣称最终桌面计算已达到 0.861 秒或已完成端到端性能验收。
