# HamHeatmap 陆地/统一水体传播验证报告

- 日期：2026-07-16
- 状态：WBM 缓存、纯海洋缺瓦片处理、陆水参数混合和沿海真实案例通过
- 主机：JAIST `gpu-753856`，Ubuntu 22.04.3 LTS，x86_64

## 1. 本轮目标

本轮关闭桌面 UI 开始前最后一项传播数据契约：让每条 ITM 地形剖面同时读取真实高程和陆水类别，按路径水体比例选择可复现的等效地表电气参数，并保证中国大陆沿海发射点仍能得到完整 200 km 圆。

```text
发射点 → 同区域 DEM + WBM 缓存准备
       → 约 90 m 高程/陆水同步剖面
       → 路径水体样本比例 f
       → land-water-v1 epsilon/sigma
       → NTIA ITM → 401×401 dBm 栅格
```

WBM、高程和热力图原始像素均不向地图前端提供查询接口。

## 2. 数据与纯海洋单元

水体源固定为 `COP-DEM GLO-90 2021_1 / AWS COG` 的 WBM 辅助文件。生产读取器验证 1200×1200、WGS-84、8-bit GeoTIFF，并按包含点的分类像素读取：

| WBM 源值 | 产品含义 | 应用类别 |
|---:|---|---|
| 0 | no water | land |
| 1 | ocean | water |
| 2 | lake | water |
| 3 | river | water |

其他像素值、尺寸、坐标系、tiepoint、分辨率或瓦片标识不匹配均阻断计算。WBM 与 DEM 使用独立缓存资产和校验和，但必须属于相同产品版本。

AWS GLO-90 不提供纯海洋地理单元。下载器只在同单元 DEM/WBM 两个固定 URL 都返回 `404` 时生成本地确定性资产：高程全为 `0 m`，WBM 全为 ocean。青岛 200 km 区域的 `N34E121`、`N34E122`、`N35E121`、`N35E122` 四个单元触发该规则，共生成 8 个资产；它们通过正式读取器解码、SHA-256、原子提交和配额核算。单边 `404` 与所有其他错误不会降级。

## 3. 模型参数

ADR-0006 固定 `land-water-v1`：

| 类别 | 相对介电常数 epsilon | 电导率 sigma |
|---|---:|---:|
| 陆地 | 15 | 0.005 S/m |
| 统一水体 | 81 | 0.010 S/m |

对每条剖面的全部样本统计水体比例 `f`：

```text
epsilon = 15 + 66 × f
sigma   = 0.005 + 0.005 × f
```

模型同时固定 `climate = 5`、`N_0 = 301`、`mdvar = 12` 和 50/50/50 中值条件。统一水体采用 NTIA 表中的淡水型参数；这符合“不区分水体”的产品要求并比把所有河湖视为高导电海水更保守，但不代表海上传播的精细物理模型。

## 4. 自动化与在线测试

新增或扩展的测试覆盖：

- WBM 分类折叠、包含像素采样、统计、地理元数据拒绝和未知值拒绝。
- 确定性纯海洋 DEM/WBM 编码后由生产读取器往返解码。
- 陆地、水体、50% 混合端点和越界比例拒绝。
- 覆盖引擎在同一约 90 m 循环内同步采样高程与水体。
- 全陆地与全水体在 1、2、5、10、20、50 km 路径上产生 ITM 差异。
- 真实 AWS DEM/WBM 成对下载和解码。
- 写入首个 128 KiB 后取消，再通过 HTTP Range 续传。
- 官方纯海洋单元成对 `404` 后生成、校验并解码；单边缺失仍是完整性错误。

三项显式网络测试合计 3/3 通过，墙钟约 6.05 秒。

## 9. 结论与限制

首版水体来源、分类、缓存、纯海洋补齐、等效参数和沿海 200 km 全圆已经形成可测试、可复现的完整链路，可以进入桌面 MVP。

尚未关闭的发布风险：

- 陆水线性混合是工程近似，未模拟海面反射、多径、潮汐、导波、城市杂波、植被或异常传播。
- 统一淡水型参数不是海水精细模型，必须用未来外场测量评估；任何修改都需要新的模型版本。
- Windows 10/11 的原子文件、Range 续传和完整桌面性能尚未实机回归。
- 2.5 GB 边界/断电恢复、签名 DEM/WBM 发布清单、合规底图、PNG/PDF 公开导出和审图仍是发布阻断项。
