# ADR-0023：英文主语言与四语言本地化基础设施

- 状态：Accepted
- 日期：2026-08-02
- 范围：React UI、诊断导出、Windows NSIS、GitHub 介绍页
- 语言：`en`、`zh-CN`、`zh-TW`、`ja-JP`

## 背景

现有桌面界面和诊断报告以简体中文硬编码，GitHub 根 README 也只有简体中文。继续直接写自然语言字符串会使新增英文、繁体中文和日文时产生四套分叉逻辑，也会让取消判断、校验错误、运行状态和导出报告无法在运行中安全切换语言。

项目所有者要求为后续开发建立多语言基础，并以英文作为 GitHub 的主介绍语言。该需求不改变传播模型、地图来源、缓存上限或离线计算语义。

## 决策

1. 前端使用固定版本 `i18next` 与 `react-i18next`，所有资源随应用本地打包；不引入远程翻译服务或自动语言探测依赖。
2. 英文是源语言与唯一 fallback。已保存设置优先于系统语言；无法识别时选择英文。
3. 用户可在应用内随时选择 English、简体中文、繁體中文或日本語。选择持久保存并更新 `<html lang>`。
4. 语言是纯展示状态。切换不得重建地图、重新计算、发起网络请求、改变缓存或丢失当前会话覆盖层。
5. 参数校验、前端错误、状态和导出模型使用稳定 key/code 加参数；业务判断不能依赖当前显示语言。
6. 跨 Rust/Tauri/validation 边界最终迁移到结构化错误 DTO。本轮在前端建立集中兼容层，不为国际化重写传播或缓存协议。
7. 诊断报告冻结导出开始时的 locale；数字使用对应 `Intl` 规则，技术单位、模型名、服务商名和署名保持原值。
8. 地图 UI 的语言与地图注记语言分离。天地图在线注记仍是供应方中文数据；英文或日文地名不属于本 ADR。
9. NSIS 包含四种安装器语言；应用内语言仍由应用自身设置管理。
10. `README.md` 为英文 canonical，三份完整翻译页通过相对链接互相导航。结构化事实清单和 CI 防止版本、哈希、测试数及关键常量漂移。

## 备选方案

- 仅复制四份 JSX：拒绝，因为状态、错误和测试会快速分叉。
- 依赖浏览器自动语言探测插件：拒绝；本项目只需少量确定映射，自写解析更小且可测试。
- 只翻译 README、不改应用：拒绝；不能满足为后续功能建立文本资源边界的目标。
- 同时把全部工程文档翻译为四种语言：暂缓；验证记录仍频繁变化，维护四份事实会增加误报风险。

## 后果

- 新功能必须同时新增四语言资源并通过 key parity 测试。
- 英文与日文较长文案增加窄窗口布局风险，需要 1080×700 回归。
- 既有 Rust 展示字符串在结构化错误协议完成前仍由集中兼容层处理；这是明确技术债，不得扩散到新组件。
- GitHub 访客默认看到英文介绍，并可一键切换到三种亚洲语言。
