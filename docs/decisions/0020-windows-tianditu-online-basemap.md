# ADR 0020：Windows 桌面在线天地图通过原生自定义协议接入

- 状态：已接受
- 日期：2026-08-01
- 范围：Windows/Tauri 桌面发行版
- 不改变：私有 validation PMTiles、EOxCloudless 和同源代理路径

## 背景

Windows 桌面版需要一条中国大陆网络环境可用的在线普通地图和卫星图路径，同时保持传播计算使用 WGS84、前端不接触地图密钥、在线瓦片不进入持久缓存。高德与腾讯的公开 Web 地图使用 GCJ-02 语义，直接把传播结果按 WGS84 叠加会产生系统性偏移；把第三方原始瓦片 URL 和共享密钥写进开源前端也不可接受。

天地图 WMTS 提供 Web Mercator 矩阵集以及普通地图、影像和对应注记图层，并要求调用方配置自己的 Key。服务可用性、配额和许可仍由用户账号及供应方规则决定，项目不承诺任意地区、运营商或时间都能访问。

## 决策

Windows/Tauri 采用用户自有天地图 Key，并固定使用四个图层：

- 普通地图：`vec_w` + `cva_w`。
- 卫星图：`img_w` + `cia_w`。
- MapLibre 只看到 `tianditu://localhost/{layer}/{z}/{x}/{y}`。
- Rust 原生层把固定协议请求转换为固定 `https://t0.tianditu.gov.cn` WMTS 请求。
- 地图与传播覆盖继续共用 Web Mercator 显示坐标；计算输入和结果地理语义仍是 WGS84。

桌面设置只提供配置、替换和清除 Key。前端输入框只保存本次编辑中的临时字符串，不写入 localStorage、sessionStorage、URL、bootstrap、错误信息或日志。Windows 使用 DPAPI 以当前用户作用域保存密文；仓库和安装包不内置公共 Key。非 Windows 构建不得用明文持久化兜底。

原生代理必须 fail closed：

- 图层白名单仅为 `vec/cva/img/cia`。
- 路径只能是规范十进制 `z/x/y`，并检查矩阵边界和固定缩放范围。
- 上游主机、协议、路径和查询结构不可由前端覆盖。
- 禁止重定向，设置连接与总体超时，并限制响应为 2 MiB。
- 同时校验 HTTP 状态、MIME 和 PNG/JPEG 图片签名。
- 返回 `Cache-Control: no-store`，不得写入项目的地图/DEM/WBM/计算缓存。
- 自定义协议只返回图片或最小错误响应，不回显 Key 和上游响应正文。

## 产品行为

- 配置有效格式的 Key 后，用户可在“地图 / 卫星”之间切换；两种模式都显示中文注记。
- 缺少 Key、断网、配额耗尽或供应方响应失败时，地图明确显示在线底图不可用，但传播参数、已缓存计算数据和诊断导出不泄漏 Key。
- 正式诊断 PNG/PDF 继续不抓取或嵌入在线供应商底图；本决策不授予瓦片再分发、离线缓存或导出许可。
- 普通浏览器 preview 和私有 validation 的能力矩阵保持原样，不能调用桌面 Key 命令。

## Windows 发行

服务器交叉构建继续生成：

- 一个便携 `HamHeatmap.exe`，目标电脑已有 WebView2 时可直接运行。
- 一个内嵌 WebView2 Offline Installer 的 NSIS 安装包，适合无运行库网络依赖的首次安装。

首版产物不带代码签名。Windows SmartScreen 可能警告，必须在公开传播前完成签名和 Windows 10/11 实机验证。GitHub Releases 可以作为开源发布源，但不能被描述为中国大陆网络始终可达的唯一下载渠道；若要正式面向大陆分发，应另外由项目所有者提供国内镜像或对象存储。

## 后果

优点：

- WGS84 传播结果与底图显示保持同一坐标语义。
- Key 不暴露给 WebView，无法被普通前端网络检查直接复制。
- 在线地图不消耗 2.5 GB 持久数据上限，也不扩大任意网络访问面。
- 地图和卫星共享同一安全代理与设置流程。

代价与未关闭项：

- 用户必须自行申请并配置天地图 Key。
- 实时浏览依赖供应方服务、配额、用户网络和许可。
- 未取得离线瓦片授权前，不提供在线底图批量下载或持久缓存。
- 仍需用真实 Key 完成 Windows 实机地图、卫星、缩放、清除 Key、断网回退和日志无密钥检查。
