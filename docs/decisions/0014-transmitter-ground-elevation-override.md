# ADR-0014：发射点地面海拔覆盖与冻结结果契约

- 日期：2026-07-27
- 状态：已采纳；实现、自动化、真实成都 auto/manual 与受管 HTTP 已通过，Windows/浏览器实测待补

## 背景

产品需求允许用户在 DEM 自动海拔之外手动覆盖发射点海拔。该输入容易与“发射天线高度 AGL”、接收点逐像素 DEM、整条传播剖面和水体分类混淆。如果手动模式完全绕过中心 DEM，用户可以在缺失、NoData 或损坏数据时继续计算，破坏“真实数据不完整即阻断”的既有规则；如果把手动值写入整个剖面，则会伪造地形而不是修正站址海拔。

结果和内部报告还需要在参数改变后保持可解释。导出时重新读取表单或 DEM 可能把“计算时使用的值”替换为后来状态，因此有效数值与来源必须成为计算结果的一部分。

## 决策

### 1. 请求字段和验证

- 请求字段固定为 `txGroundElevationOverrideM: number | null`。
- JSON 字段缺失或显式 `null` 都表示 DEM 自动，保持旧调用方兼容；有限数值表示手动覆盖。
- 手动范围固定为 `-500..=9000 m AMSL`。前端、`hamheatmap-app-service` 与 coverage 配置都验证边界；非有限数值和越界值拒绝。
- `txHeightM` 始终是独立的天线离地高度 AGL，不随地面海拔模式改变。

### 2. DEM、PFL 和 WBM 语义

覆盖计算在启动 worker 前总是读取并校验发射点中心 DEM：

1. 中心 DEM 缺失、NoData、损坏或非有限时阻断；
2. 自动模式用中心 DEM 作为有效发射点地面海拔；
3. 手动模式只在中心 DEM 校验成功后选择手动值；
4. 每条 ITM PFL 只有第一个发射端地形样点使用该有效值；
5. 后续剖面与接收点高程继续来自 DEM；
6. 发射端在内的全部 WBM 样点仍照常读取，陆水比例和 `land-water-v1` 参数不变。

手动覆盖因此是“站址地面海拔修正”，不是 DEM 缺失兜底、整体地形平移或天线高度替代。

### 3. 前端状态

- 默认模式为 DEM 自动；切到手动时使用当前已检查 DEM 值作为初始编辑值。DEM 尚未返回时来源控件禁用，事件处理也拒绝进入手动模式，不能静默物化为 `0 m`。
- 场景预设只调整功率、增益和 AGL 高度，保留当前地面海拔模式/手动值。
- 选择不同地图点会清除旧结果并重置为 DEM 自动，避免把一个站址的人工值带到另一个站址。
- “清空热力图”只清除结果，保留发射点、参数、地面海拔模式/值和缓存状态。

### 4. 结果与导出 schema

`CalculationResult` 从 schema 2 升级为 schema 3，并新增：

- `txGroundElevationM`：本次实际用于 PFL 首样点的有限 AMSL 数值；
- `txGroundElevationSource`：`dem` 或 `manual`。

`bootstrap` 与其他 AppService 响应保持 schema 2，不因计算结果字段扩展而无关升级。内部报告从 schema 3 冻结结果读取海拔和来源，不能从计算后的表单或重新检查的 DEM 推断。

历史文档中 `schemaVersion=2` 的真实 HTTP 响应仍是当时构建的有效证据，但不代表当前计算结果协议。

## 结果

优点：

- 手动修正不会掩盖中心 DEM 完整性问题；
- PFL 语义最小且可解释，AGL、接收地形和陆水模型保持稳定；
- 旧请求可继续按 DEM 自动运行；
- 新点、预设、清空和导出行为有明确状态边界；
- 导出能准确记录计算时的有效地面海拔及来源。

代价与限制：

- 手动值可能与真实地形不一致，软件只验证范围，不证明测量准确；
- 改变 PFL 首样点可能使热力图显著变化，这是用户输入的预期结果，不是 DEM 编辑；
- 结果 schema 3 的消费者必须读取新增冻结字段；bootstrap schema 不变；
- 当前实现不提供接收端海拔覆盖或整幅 DEM 校正。
