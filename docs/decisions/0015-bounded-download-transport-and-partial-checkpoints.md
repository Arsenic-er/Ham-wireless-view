# ADR-0015：有界下载传输与 partial 故障检查点

- 日期：2026-07-27
- 状态：已采纳；实现、自动化回归与既有真实 HTTPS 套件已验证，弱网/Windows 实测待补
- 补充：ADR-0005 的下载完整性与 ADR-0008 的确认式下载

## 背景

既有下载器只在构造初始 URL 时验证固定 Copernicus AWS HTTPS 前缀，并使用 HTTP 客户端默认重定向行为。合法白名单 URL 如果返回 3xx，客户端可能离开允许主机，使“初始 URL 合法”等同于“最终请求始终合法”的假设失效。

HEAD 具有总超时，但 GET 网络读没有完整的有限分阶段/总超时。用户取消令牌只在网络 read 返回后才能检查，因此无界阻塞读也会成为无界取消延迟。

下载循环在取消时会同步 partial 和 SQLite 长度；响应体读取错误或早于 Content-Length 的 EOF 却可能直接返回。这样磁盘上已经落盘的可用字节与 SQLite `size_bytes` 不一致，同一进程中的下一次用户重试可能无法安全识别该 partial。

## 决策

### 1. HTTP Agent 策略

下载服务使用统一显式 Agent 配置：

- `https_only = true`；
- `max_redirects = 0`；
- 全局请求上限 5 分钟；
- DNS 解析 5 秒；
- 连接 10 秒；
- 请求发送/请求体发送各 10 秒；
- 响应头 15 秒；
- 响应体单次等待 30 秒。

这些值是当前传输策略的一部分。修改需要单元测试、真实 HTTPS 回归和弱网验证，不能依赖客户端库默认值静默变化。

URL 仍必须通过固定 HTTPS 前缀、无用户信息、无查询、无片段和相似域名拒绝。Agent 级 HTTPS-only 与零重定向是第二层约束，不替代 URL 构造/校验。

### 2. HEAD 状态

- 只有 HTTP 200 可以提供 Content-Length、ETag 与 Range 元数据。
- HTTP 404 由上层记录为 missing；只有同一地理单元的 DEM/WBM 都明确为 404 才进入既有纯海洋生成规则。
- 其他 2xx、所有 3xx、其他 4xx 和 5xx 都是网络/完整性错误，不能当作存在对象或海洋。

### 3. partial 检查点

流式 GET 在以下三种出口执行同一检查点：

1. 用户取消；
2. 响应体 `read` 错误，包括超时；
3. EOF 早于期望 Content-Length。

检查点先对当前文件执行 `sync_all`，再把实际已写字节更新到 SQLite，然后才返回 `Cancelled` 或网络错误。写入本身、同步或索引更新失败仍作为更高优先级的本地完整性错误返回，不能假称 partial 已可靠保存。

达到完整期望大小后继续执行既有长度、可选清单哈希、本地 SHA-256、原子改名和 ready 提交；early EOF 永远不能进入 finalize。

### 4. 重试语义

应用不自动重试失败的 GET，以免在用户取消、弱网或配额边缘产生不可见后台流量。用户再次显式发起区域准备时，只有以下条件全部匹配才续传：

- 资产仍为 downloading；
- 期望总大小不变；
- 强 ETag 一致；
- 服务器声明 Range；
- SQLite partial 长度与磁盘真实长度一致且不超过期望大小。

任一条件不满足时按 ADR-0005 的规则丢弃不可信 partial 并安全重下单个资产。partial 和所有元数据继续计入十进制 2.5 GB 硬上限。

## 结果

优点：

- 重定向不能绕过固定来源白名单；
- DNS、连接、响应和整体请求都有上界，取消观察延迟不再依赖无限网络阻塞；
- 取消、超时和 early EOF 保留同样可靠的续传检查点；
- 不引入隐式自动重试，用户确认、配额和网络行为仍可预期。

代价与限制：

- 网络极慢但仍有进展时可能触发阶段超时，用户需要再次发起准备；
- 取消仍需等待当前网络 read 返回，最坏观察延迟受响应体超时约束而不是即时；
- 零重定向意味着上游若改变为重定向发布，需要显式更新固定 URL/清单并重新审查，而不能自动跟随；
- 真实弱网、系统休眠与 Windows 网络栈行为不能由脚本化 reader 或 Linux HTTPS 测试外推。
