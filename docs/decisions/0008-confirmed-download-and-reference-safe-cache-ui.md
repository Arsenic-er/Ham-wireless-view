# ADR-0008：确认式下载与引用安全的缓存管理

- 状态：Accepted
- 日期：2026-07-16

## 背景

桌面端需要把 Phase 1 已验证的 GLO-90 下载器接入新手流程，同时满足四个约束：下载前必须显示预计量并由用户确认；前端不能提交任意 URL、大小或哈希；取消不能破坏已完成资产或合法 partial；删除一个区域不能误删其他区域共享的瓦片。Tauri 后端还必须避免下载、计算和缓存管理同时打开具有独占文件锁的 `CacheStore`。

## 决策

1. 前端只向后端提交 WGS-84 发射点。`estimate_download` 在 Rust 中重新生成固定 200 km 区域计划，对白名单 HTTPS 对象执行 HEAD，并返回待准备资产数、新增字节、可续传字节、纯海洋生成数和预计总占用；不向前端暴露下载 URL。
2. 估算阶段不创建 `region_assets` 引用。只有用户确认并调用 `download_region` 后，后端才重新探测固定来源、执行整批配额/磁盘预检并登记区域。这样关闭确认弹窗不会产生空区域记录，执行也不信任过期或被修改的前端估算。
3. 下载沿用 `.partial`、Range、Content-Length、SHA-256、同目录原子改名和成对 `404` 纯海洋生成规则。取消令牌在每个资产和每个 128 KiB 网络块之间检查；取消后保留 ready 资产和合法 partial，下一次重新估算其续传量。
4. `download-progress` 只包含资产序号、字节计数和百分比，不包含 URL。应用服务按至少 0.5% 变化、250 ms 或完成事件节流，避免 128 KiB 块逐个冲击 WebView IPC。
5. `CacheStore::list_regions` 计算每个区域的就绪/partial 资产、引用字节和可回收字节。`delete_cache_region` 仍由既有多对多引用规则执行：只删除引用数归零的 final/partial 文件；共享资产保留；不自动淘汰区域。
6. Tauri 使用单一 `running_operation` 状态串行化所有会打开 `CacheStore` 的初始化、点检查、估算、下载、概览、传播计算和删除。下载和计算共享原子取消令牌，但提供语义独立的 IPC 命令。
7. 浏览器预览可以展示静态下载确认数据和缓存布局，但“下载并准备”保持禁用，不执行网络写入，也不返回模拟传播结果。

## 结果

- 用户看到的字节数来自固定来源实时探测，并在确认后再次由 Rust 验证。
- 取消后可以安全续传，且 partial 始终计入十进制 2.5 GB 上限。
- 重叠区域删除行为可解释：界面分别显示“已引用”和“可释放”，不会把逻辑区域大小误称为实际可回收空间。
- 估算需要联网并可能对一个区域执行数十次 HEAD；目前作为阻塞 worker 运行但不支持中途取消。Windows E2E 需要确认弱网络下的超时与错误文案。
- JAIST 只能验证共享 Rust 核心、真实 HTTPS 测试和浏览器界面；WebView2 事件、Windows 文件锁和系统休眠恢复仍需实机回归。
