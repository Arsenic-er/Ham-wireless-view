# ADR-0019：会话覆盖层保留与 validation 浏览器导出

- 日期：2026-08-01
- 状态：已采纳，自动化已通过，受管部署待验证

## 背景

原界面只保存一个 `CalculationResult`。用户选择新点或开始新计算时，React 会把该结果置空，MapLibre 随后删除唯一的 image source/layer，因此已完成覆盖图会消失。这不利于连续评估多个候选站点。

桌面 Tauri 已有原生保存对话框、PNG 校验和单页 PDF 导出，但私有 validation 平台的导出一直禁用。用户当前主要通过该平台验证功能，需要在不扩展服务器文件权限的前提下开始使用诊断报告导出。

## 决策

### 1. 仍保持单发射机计算

每次 ITM 请求、结果统计和导出报告只对应一个发射点。地图重叠只是多份独立结果的视觉叠放，不计算最大 dBm、不合并栅格，也不声明多发射机联合覆盖。

### 2. 会话内最多保留八个结果

- React 保存 `sessionResults: SessionCoverageResult[]`，每项冻结结果、无线电参数、完成时间和受控 ID。
- 不同坐标的新结果追加到最上层；完全相同坐标的重算替换旧项并移到最上层。
- 第九个不同坐标完成时移除最早项，避免大量 401×401 PNG、Blob 和 WebGL 纹理长期占用内存。
- 选择新点只清除当前预览与可导出选择，已完成会话层继续显示。
- “清空”删除全部已完成会话层和预览，但保留当前点、参数和数据缓存。
- 会话层不写 SQLite、项目文件或浏览器持久存储，应用重启后不恢复。

### 3. MapLibre 独立资源生命周期

每个已完成结果使用由内部 ID 派生的独立 image source、raster layer 和 Blob URL lease。历史站点通过独立 GeoJSON source 显示；当前选中站点仍使用最高层的发射点标记。desired-state 重放按结果集合增删资源，样式暂不可用时延后到 `load/styledata/idle`，清空和卸载逐项撤销 Blob URL。

### 4. 导出当前最新的单个结果

第一版不导出屏幕上的多层合成图。导出弹窗只针对当前最新且参数未过期的已完成结果，并读取计算完成时冻结的参数；选择新点后，在新结果完成前导出保持禁用。

Tauri 路径保持不变：原生保存对话框选择路径，Rust 原子写入 PNG/PDF。

validation 路径只在浏览器内执行：PNG 直接由 Blob 下载；PDF 把固定报告画布转换为高质量 JPEG，嵌入一个自包含的 A4 横向 PDF 后由 Blob 下载。服务器没有导出路由，不接收报告正文、文件名之外的目标路径或任意文件系统路径。

普通 preview 模式继续禁用真实计算和导出。

## 未采用方案

- 无限保留结果：会让 Base64、Blob 和 GPU 纹理占用无上限增长。
- 每次新点清除旧结果：与连续候选点观察需求冲突。
- 同点结果重复叠加：透明混色会造成误读，且没有独立物理意义。
- 在服务器生成或保存报告：扩大了 validation API 与文件系统权限，不符合回环验证安全边界。
- 首版合成所有覆盖层导出：需要先定义重叠语义、站点图例和报告布局，本次不隐式决定。

## 后果

- 用户可以连续计算不同站点并保留最多八层，清空行为变为删除全部会话覆盖层。
- 选择新点后旧图仍在，但当前结果完成前没有可导出的活动结果；这避免导出点位和表单混淆。
- validation 平台获得诊断 PNG/PDF 下载能力，同时服务器路由和写权限保持不变。
- 将来若要候选点比较、联合场强或项目持久化，必须另立数据模型和 ADR，不能从当前视觉叠放推断。

## 验证

自动化必须覆盖：不同点累积、同点替换、八项上限、清空全部、每层独立 source/layer 与 Blob 释放、浏览器 PNG 下载、PDF 结构、validation 能力矩阵，以及 Tauri 优先级不变。受管服务重建、健康检查和实际浏览器交互证据在部署后回填。
