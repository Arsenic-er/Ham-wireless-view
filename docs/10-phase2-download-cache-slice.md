## 1. 本轮目标

把已经验证的缓存下载器接入桌面主流程：

```text
点选发射点 → 缺少 DEM/WBM
  → 后端固定来源探测与整批配额预检
  → 显示新增量/续传量/预计占用
  → 用户确认
  → 下载或纯海洋本地生成 → 进度/取消
  → SHA-256 与原子 ready → 重新检查中心高程
  → 开始传播计算
```

同时把缓存概览推进为区域列表，支持用户确认后删除；共享瓦片不能被错误回收。

## 2. Rust 服务契约

`hamheatmap-app-service` 新增：

- `estimate_download(MapPoint)`：返回区域 ID、地理单元、ready/待准备资产、纯海洋生成数、新增字节、可续传字节和预计总占用。
- `download_region(MapPoint, AtomicBool, progress)`：重新生成和探测计划，执行原子下载，完成后重新运行 `inspect_point`，只有 DEM/WBM 全部 ready 才返回。
- `cache_overview()`：返回实际根目录用量和区域引用摘要。
- `delete_cache_region(region_id)`：调用引用安全删除并返回最新概览。

前端永远不提交 URL、Content-Length、ETag 或 SHA-256。估算阶段不创建区域引用；确认执行时后端重新探测，避免把前端显示值当作授权数据。

## 3. 下载、进度与取消

- 下载开始前一次性检查整个计划是否能在 `2,500,000,000` 字节硬上限和当前磁盘空间内完成。
- 网络资产仍使用固定 AWS HTTPS 白名单、128 KiB 流式块、Range 续传、长度检查、本地 SHA-256 和同目录原子改名。
- DEM/WBM 同一地理单元成对 `404` 时才生成确定性纯海洋资产；其他缺失继续阻断。
- 取消在资产边界和网络块之间检查。已完成资产保持 ready；合法 partial 保留并在下次估算显示为可续传。
- UI 事件按 0.5% 变化、250 ms 或完成节流，显示总字节和当前资产序号。
- Tauri 用一个 operation mutex 串行化所有会打开 `CacheStore` 的初始化、点检查、估算、下载、概览、计算和删除，避免独占锁检查/执行竞态。

## 4. 缓存区域删除

区域概览显示：

- 中心经纬度；
- ready/总资产数与 partial 数；
- 该区域引用的实际文件字节；
- 删除后真正可释放的字节。

删除仍由 `regions ↔ region_assets ↔ assets` 多对多关系控制。只有最后一个区域引用消失时才删除 final/partial 文件；共享资产和当前内存中的热力图保留。应用不执行 LRU 或任何静默淘汰。

## 9. 2026-07-27：有界下载传输与 partial 故障检查点

本节是对 2026-07-16 历史切片的安全补充，不修改当时的测试数量或运行数字。

### 9.1 固定传输策略

- 内部 URL 白名单保持为固定 Copernicus AWS HTTPS 前缀；HTTP Agent 另行强制 HTTPS-only 和零重定向，初始合法 URL 不能通过 3xx 离开白名单。
- DNS 解析、连接、发送、响应头、响应体和整次请求均有有限超时；下载不再允许在没有截止时间的网络读上无限阻塞。
- HEAD 只有 HTTP 200 可提供对象大小/ETag/Range 元数据。HTTP 404 仍只作为 DEM/WBM 同地理单元成对判定的一个输入；单边 404、3xx 或其他状态不能生成海洋资产。

### 9.2 可恢复 partial

取消、响应体读取错误和 early EOF 采用相同检查点：先 `sync_all` 已写 partial，再把实际字节数更新到 SQLite，然后返回取消或网络错误。软件不在本次操作内自动重试；用户重新发起区域准备时，只有强 ETag、Range 支持、期望总大小与磁盘/索引长度全部一致才从检查点续传，否则按既有完整性规则安全重下。

该规则保持：

- partial 始终计入十进制 2.5 GB 硬上限；
- 已完成 ready 资产不因后续网络失败回滚；
- 读取错误和早结束不是可提交的完整文件；
- 用户取消仍可在下一次显式操作中恢复，而不会被描述为后台自动重试。
